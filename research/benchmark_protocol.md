# Benchmark protocol

Status: **draft protocol**. No benchmark data has been created or evaluated yet. All sample counts are targets.

## 1. External datasets (reference only)

| Dataset | Task | Use in VERITAS | Notes |
|---|---|---|---|
| FEVER | Claim verification against Wikipedia (SUPPORTS / REFUTES / NOT ENOUGH INFO) | Verification module sanity check (E4) | Check the claim count and licence against the official release before citing |
| SciFact | Scientific claims with rationales | Domain-shift check for verification | Small (~1.4K claims) |
| HoVer | Multi-hop verification | Multi-document retrieval (E2, E3) | |
| SciClaimEval (LREC 2026) | Claims over tables and figures in papers | Table-evidence verification | Verify the paper's details before citing |

Label mapping to VERITAS verdicts (SUPPORTS → `supported`, REFUTES → `refuted`, NEI → `insufficient_evidence`) is applied at evaluation time only. These datasets do not test PDF/DOCX/XLSX provenance, which is why VERITAS-DocBench exists.

## 2. VERITAS-DocBench v1

### Composition (targets)

| Category | Gold verdict | Target |
|---|---|---|
| Numerical contradictions | `contradicted` / numerical | 50 |
| Temporal contradictions | `contradicted` / temporal | 40 |
| Entity contradictions | `contradicted` / entity | 30 |
| Logical contradictions | `contradicted` / logical | 40 |
| Contextually different | `contextually_different` | 40 |
| Insufficient evidence | `insufficient_evidence` | 50 |
| Consistent | `supported` (both claims) | 50 |
| **Total** | | **300** |

### Construction

* **Synthetic subset (~250):** generated by templated scripts in the style of `scripts/make_sample_documents.py`. Gold claims, entity mappings, evidence spans and source references come from the template, so labels are created automatically and are exact. Generators are seeded and version-controlled.
* **Realistic subset (30–50):** publicly licensed documents, annotated by hand. This subset decides the final conclusions; synthetic results alone are not reported as the headline.
* Formats are balanced across PDF, DOCX and XLSX, and at least 30% of samples have their evidence in tables.

### Sample record

Each sample is a directory with the source documents plus a `gold.json` validated against the contracts in `core/contracts.py`. It contains: source documents; gold `Claim`s with `Evidence` (exact `SourceLocation`); gold entity clusters; the gold `Conflict` or `VerificationResult`; and an annotation note explaining the decision.

### Splits

Fixed `dev` (20%) and `test` (80%) splits by sample, recorded in `splits.json`. Prompts and thresholds are tuned on `dev` only. `test` is evaluated once per frozen configuration.

## 3. Metrics

| Module | Metric | Matching rule |
|---|---|---|
| Parsing | Text recall vs. source text; provenance accuracy (span location equals gold location) | Normalised whitespace |
| Claim extraction | P / R / F1 | Subject (after resolution), predicate, value (with unit, ±0 tolerance), modality and period must all match |
| Entity resolution | Pairwise P / R / F1 | Over mention pairs |
| Retrieval | Recall@5, Recall@10, MRR | Gold evidence span id in the top-k |
| Contradiction detection | P / R / F1 for `contradicted`; confusion matrix over all verdicts | Per claim pair |
| Evidence grounding | Evidence P / R | Predicted evidence span ids vs. gold |
| Citation completeness | Claims with ≥ 1 valid citation ÷ factual claims generated | "Valid" = resolves to an existing located span |
| Citation correctness | Citations whose span supports the claim ÷ citations checked | Judged against gold; manual audit of a 10% sample |
| Hallucination | Unsupported-claim rate in reports | Claims with no supporting gold evidence |
| Abstention | Abstention precision / recall against `insufficient_evidence` gold | |
| System | Latency per document and per claim, peak RSS, throughput | Measured on the reference M2 / 16 GB machine |

Formulas: P = TP / (TP + FP), R = TP / (TP + FN), F1 = 2PR / (P + R).

## 4. Reporting rules

* Every result records: git commit, model and quantisation, decoding parameters, dataset version and split, hardware, and wall time.
* Results go to `experiments/<area>/<run-id>/` as JSON, and are summarised only from those files.
* Report 95% bootstrap confidence intervals for F1 on the test split.
* No result is quoted in the README unless it was produced by a committed configuration.
